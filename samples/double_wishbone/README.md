# ダブルウィッシュボーン式サスペンション（`assets/scenes/double_wishbone.xml`）の生成

`samples/` は見本シーンの素材を作るためのもの（エンジン本体のビルドにも実行にも
使わない）。`assets/scenes/double_wishbone.xml` と部品のメッシュ
`assets/models/double_wishbone/*.glb` はここのスクリプトで作っている。

```bash
pip install manifold3d trimesh numpy scipy networkx
cd samples/double_wishbone
python3 meshes.py                        # 部品の .glb（V6 の ../v6_engine/meshlib.py を使う）
python3 gen.py --report                  # レバー比・ばね・キャンバー変化などの表だけ
python3 gen.py --rig-text rig_filled.txt # 制御器の数式（値を埋めたもの）
# rig_filled.txt をエンジンの formulaFromText でノードの <formula> に起こして
python3 gen.py --formula-xml rig_formula.xml   # ../../assets/scenes へ書く
```

数式 → ノードの変換はエンジンの変換器（`src/formula/FormulaText.cpp`）を通す
（Python に写すと 2 か所の定義になるため）。文書層だけの小さなプログラム
（`formulaFromText` → `formulaElement` → `xml::write`）で作る。手で直すだけなら、
シーンを開いて 🧮 rig の「📝 数式で編集」で直してもよい（数式は `<source>` に残っている）。

## 何をしているか

クォーターカーの加振試験台。**リンクの拘束・ばね・ダンパはすべて Chrono**:

| 部品 | Chrono の拘束 / 要素 |
|---|---|
| 車体の 1/4（400 kg） | 世界に `slide`（上下だけ） |
| ロア / アッパー A アーム | 車体に `hinge`（前後方向の軸） |
| アップライト（ナックル） | 上下のアームに `ball` |
| タイロッド | 車体（ラック）に `universal`、ナックルアームに `ball` |
| ホイール | アップライトに `hinge`（ハブ、自由回転） |
| コイルオーバー | 上端 `universal`・シリンダとロッドの `slide`・下端 `ball`、ばね + ダンパは `spring`（`ChLinkTSDA`、自然長に予圧ぶん） |
| タイヤ | ホイール中心 ⇄ 加振台の縦の `spring`（250 kN/m） |
| 加振台 | 世界に `slide` の位置モータ |

拘束はちょうど釣り合っている（冗長な拘束なし）。自由度は車体の上下・サスペンションの
上下・ホイールの回転・加振台の 4 つ。A アームは 1 本の `hinge` で、車体側の 2 点の
ブッシュは見た目。部品どうしは当たらない（全部 `layer="1" nocollide="0 1"`）。

制御器 `rig`（`rig.txt`）は加振台の目標の高さを作り（静置 / 段差 / 正弦掃引 / 正弦）、
計測値をスコープに出す: 路面・車体・ホイールの変位、ストローク、キャンバー変化と
トー変化（アップライトのオイラー角からホイール軸を組み直して求める）、コイルの力と
タイヤの力（符号付き。負 = 実車ならタイヤが浮いている）、車体の上下加速度。

## 見た目（meshes.py）

部品はボディごとに 1 個の .glb（そのボディの座標系 = `gen.body_frames()` の中心と回転で
作るので、シーンではプレハブの部品として pos 0・倍率 1 で付くだけ）。ボディは形（geom）を
持たない（質量だけ = `addFrame`）ので、部品どうしは当たらない。色は役割ごと:

| 部品 | 色 |
|---|---|
| 車体（ばね上）・ブラケット・ストラットタワー | 紺 |
| ロア A アーム | 橙 |
| アッパー A アーム | 緑 |
| ナックル（アップライト）| 銀（キャリパは黄） |
| タイロッド | 青 |
| コイルばね | 赤 |
| ダンパ本体 / ピストンロッド | 黒 / クロム |
| ボールジョイント / ブッシュ | 真鍮 / 黒 |
| 加振台 | 黄 |

コイルばねは上下 2 つのボディ（`shock_rod` = ロッド・アッパーマウント側、`shock_body` =
ダンパ本体側）に半分ずつ載せてある。剛体なので形は伸び縮みしないが、縮むと真ん中で
重なり、伸びると間が開くので、ばねの長さの変化は見える。

カメラは `cam0` = 車の内側・斜め前（ホイールに隠れずに全部の部品が見える）、
`front` = 真正面（キャンバー変化）、`outside` = 外側の斜め前。

## 寸法と釣り合い

- 上の定数（ハードポイント・質量・目標の固有振動数と減衰比・タイヤのばね）が唯一の定義。
- コイルのばね定数は「ばね上の固有振動数 1.4 Hz（タイヤと直列）」から、レバー比
  （ばねの長さの変化 / ホイールの上下）の 2 乗で割って出す。ダンパはばね上の減衰比 0.3。
- **設計姿勢 = 1G の釣り合い**: タイヤの予圧 = 全質量 × g、コイルの予圧は仮想仕事
  （サスペンションを微小に動かしたときの重力・タイヤ力・ばね力の仕事の和が 0）で求め、
  どちらもばねの自然長（`distance`）を予圧ぶん長くしてある。だからシミュレートを
  始めても沈まない。
- アッパーアームを短くした SLA（short-long arm）なので、バンプでネガティブキャンバーが
  付く。タイロッドの長さと高さで決まるバンプステア（トー変化）も出る。
  `--report` の表が運動学で解いた値（Chrono で回した値と比べられる）。

## 確認

本物の Chrono 9.0.0（Core）をビルドし、WizEngine の `PhysicsWorld` を同じソースのまま
使ってこの文書を組み、制御器 `rig` を C++ インタプリタで回して確かめた:

- 静置: 車体の沈み 0.07 mm（予圧どおり釣り合う）
- 段差 30 mm: 車体は約 1.4 Hz で減衰しながら追従
- 正弦掃引 30 mm: ストローク ±60 mm のとき、キャンバー変化は −2.07 / +1.03°
  （`--report` の表では −1.99 / +1.04°）
- 正弦 13 Hz・30 mm: ホイールホップでタイヤ力が負まで振れる（実車なら浮く）
- NaN なし。実時間の約 10 倍の速さで回る

エンジン本体（Scene・ブラウザ）での実行はまだ確認していない。
